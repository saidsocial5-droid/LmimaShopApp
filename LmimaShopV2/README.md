# LmimaShop V2 — نظام كاشير وإدارة متجر

نظام نقاط بيع (POS) عربي، مبني من الصفر، يعمل على سطح المكتب مع خادم ويب مدمج،
ويتصل به هاتف عبر تطبيق ويب تقدمي (PWA) أو حزمة APK.

**الإصدار:** 2.0.0

---

## نظرة عامة

نظام كاشير V2 مكتوب من الصفر، مبني على:

| المكوّن | التقنية |
|---|---|
| تطبيق سطح المكتب | WPF / .NET 10 (Windows x64) |
| قاعدة البيانات | MySQL 8 (`LmimaShopV2DB`) |
| خادم الـ API المدمج | HTTP/JSON + SSE على المنفذ **8090** |
| تطبيق الهاتف | PWA (HTML/CSS/JS) يُقدَّم من خادم سطح المكتب |
| المزامنة | مزامنة تفاضلية (Delta) مع دعم العمل دون اتصال |

يعمل الخادم داخل تطبيق سطح المكتب نفسه، لذلك لا توجد خدمة ويب منفصلة تحتاج إلى
إدارة. يخدم الخادم واجهة الهاتف على `http://<IP-الكمبيوتر>:8090` ويوفر نقاط
الـ API الموثقة في [`docs/API_SPEC.md`](docs/API_SPEC.md).

---

## المتطلبات

- **.NET 10 SDK** (لبناء وتشغيل تطبيق سطح المكتب).
- **MySQL Server 8.x** يعمل على نفس الجهاز (أو جهاز متاح على الشبكة).
- **متصفح حديث** على الهاتف (Chrome / Edge / Safari) لتشغيل الـ PWA.
- نظام تشغيل Windows 10/11 نسخة 64-bit لتطبيق سطح المكتب.

اختياري (للإصدار فقط):

- **Inno Setup 6** لبناء ملف التثبيت `installer/LmimaShopV2.iss`.
- **Java** (أو الـ JRE المرفق في `ApkBuilderTools`) و**apktool** و**uber-apk-signer**
  لبناء APK.

## البناء

من جذر المستودع (المجلد الأعلى الذي يحتوي `LmimaShopV2`):

```powershell
dotnet build LmimaShopV2/desktop/LmimaShopV2.Desktop.csproj -c Release
```

أو من داخل مجلد `LmimaShopV2`:

```powershell
dotnet build desktop/LmimaShopV2.Desktop.csproj -c Release
```

الناتج:

```
desktop\bin\Release\net10.0-windows\LmimaShopV2.Desktop.exe
```

## التشغيل

1. **قاعدة البيانات:** أنشئ قاعدة `LmimaShopV2DB` ثم استورد المخطط:

   ```powershell
   mysql -u root -p -e "CREATE DATABASE IF NOT EXISTS LmimaShopV2DB CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"
   mysql -u root -p LmimaShopV2DB < db\schema.sql
   ```

   أو دع التطبيق ينشئ القاعدة والمخطط تلقائياً عند أول تشغيل (إن كان مستخدم
   MySQL يملك صلاحية `CREATE`).

2. **تشغيل التطبيق** — إما بالنقر على الـ exe أو عبر السكربت:

   ```powershell
   .\scripts\start_desktop.ps1
   ```

   السكربت يبني نسخة Release تلقائياً إن لم تكن موجودة ثم يشغّل التطبيق.

3. **تسجيل الدخول الأول:**

   - المستخدم: `admin`
   - كلمة المرور: `admin123`

   > **مهم:** غيّر كلمة المرور الافتراضية فوراً من شاشة المستخدمين/الإعدادات.

4. **توليد رمز الاقتران:** افتح **الإعدادات** ← **اقتران الهاتف**، ثم اضغط
   توليد رمز. يظهر رمز من 6 أرقام صالح لمدة **120 ثانية** مع رمز QR يحتوي
   `http://<IP>:8090/#pair=<الرمز>`.

5. **توصيل الهاتف:** وصّل الهاتف بنفس شبكة الواي فاي، افتح المتصفح على
   `http://<IP-الكمبيوتر>:8090`، ثم أدخل الرمز أو امسح رمز QR.

> **للتطوير فقط:** يمكن تقديم واجهة `mobile/` على المنفذ **8091** دون تشغيل
> تطبيق سطح المكتب عبر `.\scripts\start_mobile_server.ps1`. هذا الخادم بلا
> مصادقة ومخصص للاختبار المحلي فقط؛ في الإنتاج يخدم خادم سطح المكتب (8090)
> مجلد `mobile/` نفسه.

## الأمان في V2

اتُّخذت الإجراءات التالية لمعالجة ثغرات الإصدار الأول:

- **مصادقة Bearer على كل نقاط الـ API** باستثناء `GET /api/ping` و`POST /api/pair`
  والملفات الثابتة للـ PWA (التي لا تحتوي بيانات). لا يُقبل الرمز في سلسلة
  الاستعلام.
- **رمز اقتران عشوائي** من 6 أرقام (مولّد تشفيرياً)، صالح **120 ثانية** فقط،
  مع مقارنة ثابتة الزمن وحد أقصى **5 محاولات في الدقيقة لكل IP** (استجابة 429).
- **الرموز مخزّنة كتجزئة SHA-256** في جدول `devices` — لا يُحفظ الرمز الأصلي.
- **حماية Path Traversal** عند تقديم ملفات الـ PWA والصور: رفض المسارات التي
  تحتوي `..` أو أحرفاً غير صالحة، والتحقق من أن المسار النهائي يقع داخل جذر
  المجلد المسموح.
- **مسار دفع واحد فقط:** كل عمليات البيع تمر عبر `CheckoutService` نفسه، سواء
  من واجهة سطح المكتب أو من `POST /api/checkout` أو من `sale_create` في المزامنة.
  هذا يمنع اختلاف قواعد المخزون والائتمان بين الواجهتين.
- **بيانات اعتماد مشفّرة محلياً** عبر Windows DPAPI، ولا تُكتب كلمات المرور في
  ملفات نصية داخل المستودع.
- **لا توجد بيانات حقيقية في المستودع:** لا قاعدة بيانات، ولا نسخ احتياطية، ولا
  صور عملاء، ولا ملفات تصدير.

## الإصدار والتحديث

### 1) نشر تطبيق سطح المكتب

```powershell
.\scripts\publish.ps1
```

يُنتج نسخة **self-contained / single-file** في `dist\publish\` مع نسخ مجلد
`mobile/` بجانب التطبيق ليخدمه الخادم المدمج. كما يحتفظ بنسخة مرحلية في
`desktop\bin\Release\net10.0-windows\publish\` يستخدمها ملف التثبيت.

### 2) بناء ملف التثبيت (Inno Setup)

```powershell
iscc installer\LmimaShopV2.iss
```

يفترض السكربت وجود مخرجات `scripts\publish.ps1` في
`desktop\bin\Release\net10.0-windows\publish\`. ملف التثبيت **لا يرفق** قاعدة
بيانات ولا أي بيانات شخصية.

### 3) بناء APK للهاتف

يُبنى ملف APK من مجلد `mobile/` عبر **apktool** و**uber-apk-signer**:

```powershell
.\scripts\build_apk.ps1
```

- أدوات البناء تُقرأ من `..\ApkBuilderTools\` (خارج مجلد V2) ويمكن تجاوز مساراتها
  بمعاملات `-ApkToolPath` و`-SignerPath` و`-JavaPath`.
- يحتاج السكربت إلى قالب APK محلي في `templates\LmimaShopV2Template.apk`، وهو
  **غير مُرفق بالمستودع**. يُنشأ مرة واحدة: مشروع Android فارغ بنشاط WebView
  يحمّل `file:///android_asset/index.html` (مع `usesCleartextTraffic="true"`)،
  ثم يُبنى ويُحفظ كقالب، أو يُفكّ بـ `apktool d` ويُعاد بناؤه. راجع رسالة الخطأ
  في السكربت للخطوات التفصيلية.
- الناتج: `dist\LmimaShopV2.apk` موقّع بتوقيع **debug** (مناسب للاختبار والتوزيع
  اليدوي، وليس للنشر على Google Play).

يمكن استخدام الـ PWA مباشرة من المتصفح دون بناء APK: أضف الصفحة إلى الشاشة
الرئيسية من قائمة المتصفح.

## النسخ الاحتياطي

```powershell
.\scripts\backup_db.ps1
```

- يُنشئ نسخة `mysqldump` لقاعدة `LmimaShopV2DB` في
  `%USERPROFILE%\Documents\LmimaShopV2Backups` افتراضياً (خارج المستودع).
- يحتفظ بآخر **14** نسخة ويحذف الأقدم.
- تمرير كلمة المرور يتم عبر متغير البيئة `MYSQL_PWD` وليس في سطر الأوامر، ويدعم
  ملف `.my.cnf` عبر المعامل `-MyCnfPath`.

## ملاحظة صريحة

**لا توجد نسخ احتياطية ولا بيانات زبائن داخل هذا المستودع — ولا يجوز وضعها فيه.**
جميع النسخ الاحتياطية وقواعد البيانات الحقيقية وملفات التصدير تبقى خارج
المستودع (المسار الافتراضي للنسخ هو `Documents\LmimaShopV2Backups`). عند ترقية
بيانات من الإصدار الأول، انقلها عبر أدوات ترحيل مخصصة وبموافقة صاحب البيانات،
ولا تنسخ ملفات قاعدة البيانات أو النسخ الاحتياطية إلى Git.
